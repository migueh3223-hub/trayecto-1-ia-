# NEUROSTUDY — ULTIMATE MASTER DEVELOPMENT PROMPT V4

## Intelligent Academic Productivity, Cognitive Learning & Personal Development Platform

# 1. ROLE AND PROJECT VISION

Act as a Senior Full-Stack Developer, Software Architect, Professional UI/UX Designer, Supabase Specialist, Educational Technology Developer, Database Architect, and Responsive Web Development Expert.

Your mission is to design and develop **NeuroStudy**, a modern, intelligent, responsive, secure, and fully functional academic productivity platform.

NeuroStudy helps students organize academic responsibilities, manage their time, improve their learning habits, maintain concentration, prepare for examinations, manage academic projects, and monitor their personal development.

This application must be much more than a traditional calendar, task manager, or study planner.

It must function as a personalized academic ecosystem that understands:

- Who the student is.
- What type of education they are pursuing.
- What subjects or courses they study.
- What their academic goals are.
- How much time they have available.
- What activities they need to complete.
- Which activities depend on other activities.
- Which areas they need to improve.
- How their academic progress evolves over time.

### Core slogan

"Organize Your Time. Train Your Mind. Evolve Your Learning."

### Main philosophy

NeuroStudy must help students answer four important questions:

1. What do I need to do?
2. What should I learn or improve?
3. How can I concentrate better?
4. How much progress am I making?

Build the entire application around these four principles.

### Critical development rules

- Do not build disconnected pages.
- Do not create duplicate task management systems.
- Do not create separate databases for individual modules.
- Do not replace working functionality with static mockups.
- Do not remove existing functionality when adding new features.
- Every module must communicate with the same authenticated student account and shared Supabase database.
- Every feature must be responsive.
- Every visible button must have a real function.
- Preserve existing information when modifying the project.
- Do not fabricate analytics or academic results.
- Do not claim that a feature is functional when it is only a visual placeholder.

Before modifying an existing project, inspect its file structure, existing functionality, database relationships, migrations, and dependencies.

Implement changes incrementally and preserve all working components.

# 8. THE NEUROSTUDY ACADEMIC ENGINE

Create a centralized application architecture called:

**NEUROSTUDY ACADEMIC ENGINE**

This is the most important engineering improvement in V4.

It is not another user-facing page.

It is the central coordination system that connects PLAN, THINK, FOCUS, EVOLVE, and the Supabase database.

## 8.1 Main responsibilities

The Academic Engine must coordinate:

- Tasks.
- Subjects.
- Exams.
- Exam preparation sessions.
- Projects.
- Study sessions.
- Goals.
- Knowledge topics.
- Notifications.
- Academic reports.
- Recommendations.
- Calendar events.
- Academic history.

## 8.2 Shared domain services

Create reusable services with clearly separated responsibilities.

Examples:

`taskService.js`

Manages creation, editing, deletion, completion, dependencies, and rescheduling.

`calendarService.js`

Combines tasks, exams, project milestones, and study sessions into one academic calendar.

`academicService.js`

Manages academic profiles, subjects, terms, and goals.

`examPrepService.js`

Manages exams, topics, preparation plans, and results.

`focusService.js`

Manages focus sessions, timers, and study history.

`notificationService.js`

Centralizes notification creation, scheduling, and preferences.

`analyticsService.js`

Calculates academic indicators using real saved information.

`recommendationEngine.js`

Creates transparent recommendations using real student data.

`resourceService.js`

Manages study library resources.

`projectService.js`

Manages academic projects and dependencies.

## 8.3 Central activity coordination

When an important action happens, update all relevant views.

Example:

When a student completes a JavaScript task:

1. Update the task in Supabase.
2. Register the relevant activity event.
3. Update PLAN.
4. Recalculate Dashboard information.
5. Update weekly progress.
6. Update relevant project progress.
7. Update academic history.
8. Recalculate workload.
9. Update recommendations when relevant.

Avoid duplicating database records or business logic.

Use shared service functions and a consistent data-refresh strategy.

Database persistence remains the source of truth.

## 8.4 Event architecture

Use meaningful domain events such as:

- task.created.
- task.updated.
- task.completed.
- task.rescheduled.
- exam.created.
- exam.updated.
- study_session.completed.
- quiz.completed.
- project.milestone_completed.
- goal.completed.

Use these events to coordinate relevant UI updates, notifications, and analytics.

Do not depend solely on browser custom events for persistent operations.

Use Supabase for durable data and Realtime for synchronization.

- File access follows Storage policies.

Use:

- Clear module responsibilities.
- Reusable functions.
- Consistent naming.
- Error boundaries at appropriate application-service layers.
- Input validation.
- Safe asynchronous operations.
- Loading states.
- Structured error reporting.

Avoid unnecessary dependencies.

Do not add complex infrastructure without a clear requirement.
